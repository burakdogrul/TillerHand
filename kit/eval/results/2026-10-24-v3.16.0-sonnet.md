- **No difference in correctness could be measured.** Both conditions passed all hidden tests. The tasks stayed easy for Sonnet (ceiling effect).
- **The kit followed the process.** In all three tasks it wrote the test before the code and saw it red, ran the gate (`gate.mjs --run`), and gave an acceptance id.
- **The run without the kit added no test when fixing the bug.** It reported "I did not run the fix separately to try it". The run with the kit left a regression test for the same bug.
- **The kit costs about 2× in tokens and cost.** Part of this is fixed load: rules, hooks and command text enter every session.
- **Next step:** Harder tasks are needed (multi-step, implicit requirements, traps). The tests the agent writes must also run against faulty code: does the remaining test catch the bug? At least 3 repeats per cell.

## Validity note (after review)

This measurement must be run again. The kit-condition folders inherited the personal `.claude/settings.local.json` file (~147 permission rules) from the kit's local copy; the run without the kit did not. The bug was in `kit.mjs init` and was fixed in 3.16.2. Also:

- The statement "wrote the test before the code, ran the gate" is the agent's own claim; the harness does not measure it.
- The "Added tests" column counts `test(` blocks, not coverage. The 11 to 3 difference may overstate the coverage difference.
- The `security-owner` hidden test expects exactly 401 for a request with no header; the task text only says "must be rejected".
